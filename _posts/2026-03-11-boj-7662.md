## 문제 링크
[https://www.acmicpc.net/problem/7662](https://www.acmicpc.net/problem/7662)

## 문제 설명
이중 우선순위 큐는 다음 연산을 지원한다.

- I n : 정수 n을 자료구조에 삽입한다.
- D 1 : 최댓값을 삭제한다.
- D -1 : 최솟값을 삭제한다.

자료구조가 비어있는데 삭제 연산이 들어오면 무시한다.
각 테스트케이스마다 모든 연산을 수행한 뒤,
비어있으면 "EMPTY"를 출력하고, 아니면 최댓값과 최솟값을 출력한다.

---

## 풀이 전략 (Approach)
이 문제는 최댓값과 최솟값을 모두 빠르게 삭제해야 하므로,
최대 힙과 최소 힙을 함께 쓰고 “지연 삭제(lazy deletion)”로 동기화하는 방식으로 해결합니다.

### 1. 상태 정의 및 알고리즘 도출
- 최대 힙 `max_pq` : 최댓값을 빠르게 꺼내기 위한 힙
- 최소 힙 `min_pq` : 최솟값을 빠르게 꺼내기 위한 힙
- `visited[id]` : 해당 id로 삽입된 원소가 아직 “유효(삭제되지 않음)”한지 표시

핵심 아이디어(지연 삭제)
- 삽입할 때마다 고유 id(여기서는 i)를 부여하고,
  같은 Node를 최대 힙/최소 힙에 모두 넣는다.
- 삭제할 때는 한쪽 힙에서 top을 꺼내 삭제 표시(visited=false)만 하고,
  다른 힙에는 그대로 남겨둔다.
- 이후 다른 힙에서 top을 꺼낼 때, 이미 visited가 false인 노드는 “이미 삭제된 값”이므로 pop으로 제거하며 정리한다.
- 출력 직전에도 두 힙의 top을 한 번 더 정리(pop)해서 실제 최댓값/최솟값이 top에 오도록 만든다.

## 코드 (C++)
```cpp
#include <iostream>
#include <queue>
#include <vector>

using namespace std;

struct Node
{
    int num;
    int id;
};

struct MaxCmp
{
    bool operator()(const Node& a, const Node& b) const
    {
        return a.num < b.num;
    }
};

struct MinCmp
{
    bool operator()(const Node& a, const Node& b) const
    {
        return a.num > b.num;
    }
};

priority_queue<Node, vector<Node>, MaxCmp> max_pq;
priority_queue<Node, vector<Node>, MinCmp> min_pq;

int t;
int k;
vector<bool> visited;

void init()
{
    cin >> k;

    while (!max_pq.empty())
        max_pq.pop();
    while (!min_pq.empty())
        min_pq.pop();

    visited.assign(k, false);

    for (int i = 0; i < k; ++i)
    {
        char op;
        cin >> op;

        if (op == 'I')
        {
            int tmp;
            cin >> tmp;

            Node node = { tmp, i };
            max_pq.push(node);
            min_pq.push(node);
            visited[i] = true;
        }
        else if (op == 'D')
        {
            int op_num;
            cin >> op_num;

            if (op_num == 1)
            {
                while (!max_pq.empty() && !visited[max_pq.top().id])
                    max_pq.pop();

                if (!max_pq.empty())
                {
                    visited[max_pq.top().id] = false;
                    max_pq.pop();
                }
            }
            else if (op_num == -1)
            {
                while (!min_pq.empty() && !visited[min_pq.top().id])
                    min_pq.pop();

                if (!min_pq.empty())
                {
                    visited[min_pq.top().id] = false;
                    min_pq.pop();
                }
            }
        }
    }
}

void solve()
{
    while (!max_pq.empty() && !visited[max_pq.top().id])
        max_pq.pop();

    while (!min_pq.empty() && !visited[min_pq.top().id])
        min_pq.pop();

    if (max_pq.empty() || min_pq.empty())
        cout << "EMPTY\n";
    else
        cout << max_pq.top().num << ' ' << min_pq.top().num << '\n';
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> t;

    while (t--)
    {
        init();
        solve();
    }

    return 0;
}
```

## 복잡도 분석
### 1. 시간복잡도 : $$O(K \log K)$$ (테스트케이스당)
각 연산에서 힙 push/pop이 발생할 수 있고, 힙 연산은 $$O(\log K)$$ 입니다.
지연 삭제로 인해 top에서 “이미 삭제된 노드”를 여러 번 pop할 수 있지만,
각 노드는 최대 한 번씩만 실제로 제거(pop)되므로 전체적으로 연산 수는 상수 배만 증가합니다.
따라서 테스트케이스당 전체 시간복잡도는 $$O(K \log K)$$ 입니다.

### 2. 공간복잡도 : $$O(K)$$
최대 힙/최소 힙에 원소들이 저장될 수 있고,
visited 배열도 크기 K이므로 $$O(K)$$ 공간이 필요합니다.
